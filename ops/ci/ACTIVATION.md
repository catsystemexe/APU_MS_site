## SHA-bound authorization contract

`once` authorizes one exact source SHA, not a time window or subsequent branch pushes. The verified latest deployment must not already identify that SHA in `workers/commit_sha`; this is checked both at initial preflight and again immediately before upload. An already deployed matching source is rejected without uploading. A successful run does not clear variables or change modes. A rerun that observes the successful latest deployment is rejected. `auto` requires the same global gate and all existing source/target/isolation/production checks, but does not require or use an approved SHA. Only a separate operator decision may select `auto`.

This is **SHA-bound authorization with redundant-deployment protection, not an unconditional exactly-once distributed execution guarantee**. External changes can race the last read; a failed postflight, lost runner or intervening different deployment can leave a rerun eligible. GitHub concurrency serializes this workflow only. Never infer one-use credentials, atomic consumption or automatic promotion from `once`.
